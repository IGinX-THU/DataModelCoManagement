# 2026-03-14 数据源新增与详情改造设计（已更新）

## 背景
系统历史上在新增数据源时要求填写挂载路径并用于注册引擎。当前需求已明确取消挂载路径，统一以路径前缀（ts/rt）管理，并扩展详情展示能力。

## 目标
- 新增数据源仅需连接参数即可完成 IGinX 存储引擎注册，并写入元数据表。
- 完全移除 `mountPath` 字段及其校验/存储/展示逻辑。
- 导入/查询/维护统一直接使用业务路径，不再拼接挂载路径。
- 数据源详情展示 IGinX 存储引擎信息与 SHOW COLUMNS 路径列表。

## 非目标
- 不改动资源树的展示形态（仅路径来源改为 IGinX 全量列路径）。

## 方案概述
1. **新增数据源简化**
   - 前端新增数据源表单移除“挂载路径”输入。
   - 后端删除 `mountPath` 字段与相关校验。
   - `ADD STORAGEENGINE` 仅使用连接参数，不再追加 `data_prefix`。

2. **数据源详情扩展**
   - 详情接口返回元数据 + 存储引擎列表 + SHOW COLUMNS 路径列表。

3. **路径处理统一**
   - 时序路径统一按 `ts.*` 前缀。
   - 结构化路径统一按 `rt.schema.table` 规则。

## 接口设计
- **新增数据源**（现有接口）
  - `POST /api/v1/data/sources`
  - 请求体移除 `mountPath`。

- **数据源详情（新增）**
  - `GET /api/v1/data/sources/{id}/detail?limit=200`
  - 返回结构：
    - `meta`：元数据表记录（DataSourceVO）
    - `engines`：存储引擎列表（StorageEngineVO）
    - `columns`：SHOW COLUMNS 结果（ColumnVO 列表）

## 数据结构
- `StorageEngineVO`
  - `ip`, `port`, `type`, `schemaPrefix`, `dataPrefix`, `hasData`, `readOnly`, `extra`
- `ColumnVO`
  - `path`, `dataType`
- `DataSourceDetailVO`
  - `meta`, `engines`, `columns`

## 前端改动
- 新增数据源弹窗：移除挂载路径输入与相关提示文案。
- 数据源详情弹窗：增加存储引擎列表与 SHOW COLUMNS 路径列表。

## 错误处理
- IGinX 不可用时：详情接口返回明确错误信息。
- SHOW COLUMNS 查询失败：返回空列表并携带提示信息。

## 测试
- 新增数据源不包含 `mountPath` 字段。
- 详情接口：引擎列表与 SHOW COLUMNS 列表返回逻辑。

## 风险与对策
- **风险**：路径前缀不规范导致查询失败。
- **对策**：前端输入校验 + 后端统一规范化（ts/rt）兜底。

## 关键决策
- 完全移除 `mountPath`。
