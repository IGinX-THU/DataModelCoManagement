# 2026-03-14 数据源新增与详情改造设计

## 背景
当前系统在新增数据源时要求填写挂载路径，并以该路径注册 IGinX 存储引擎；数据源详情仅展示元数据表中的信息。现在需要简化新增流程并扩展详情展示能力。

## 目标
- 新增数据源仅需连接参数即可完成 IGinX 存储引擎注册，并写入元数据表。
- 数据源详情同时展示：
  - IGinX 存储引擎信息（全量）
  - SHOW COLUMNS 返回的路径/类型列表（全量，支持限制条数）

## 非目标
- 本次不改动“数据资源库树形结构”。
- 不在新增数据源阶段强制校验 ts/rt/models 前缀规则。
- 不调整导入/查询/维护等业务逻辑对 mountPath 的依赖。

## 现状
- `DataSourceCreateRequest` 强制 `mountPath` 非空。
- `DataSourceServiceImpl.createDataSource` 对挂载路径进行校验、规范化，并用于 `ADD STORAGEENGINE` 的 `data_prefix` 参数。
- 数据源详情弹窗仅展示元数据表字段，不展示 IGinX 引擎与 SHOW COLUMNS 信息。

## 方案概述
1. **新增数据源简化**
   - 前端新增数据源表单移除“挂载路径”输入。
   - 后端允许 `mountPath` 为空：
     - 取消创建请求中的 `@NotBlank` 约束。
     - 创建时若为空，不进行挂载路径校验与冲突检查。
     - 仍写入元数据表，`mount_path` 可为空。
   - `ADD STORAGEENGINE` 仍执行：
     - 当 `mountPath` 为空时，不追加 `data_prefix`。

2. **数据源详情扩展**
   - 新增详情接口：返回元数据 + 存储引擎列表 + SHOW COLUMNS 结果。
   - 详情中的存储引擎为“全量列表”，不与元数据表做一一绑定。
   - SHOW COLUMNS 结果默认返回前 N 条（可通过参数控制）。

## 接口设计
- **新增数据源**（现有接口保持）：
  - `POST /api/v1/data/sources`
  - `mountPath` 变为可选字段。

- **数据源详情（新增）**：
  - `GET /api/v1/data/sources/{id}/detail?limit=200`
  - 返回结构：
    - `meta`：元数据表记录（沿用 DataSourceVO）
    - `engines`：存储引擎列表（StorageEngineVO）
    - `columns`：SHOW COLUMNS 结果（ColumnVO 列表）

## 数据结构
- `StorageEngineVO`
  - `ip`, `port`, `type`, `schemaPrefix`, `dataPrefix`, `hasData`, `readOnly`, `extra`
- `ColumnVO`
  - `path`, `dataType`
- `DataSourceDetailVO`
  - `meta`, `engines`, `columns`

## 前端改动
- 新增数据源弹窗：移除挂载路径输入与相关提示文案。
- 数据源详情弹窗：增加两个区域（或 Tab）：
  - 存储引擎列表
  - SHOW COLUMNS 路径列表

## 错误处理
- IGinX 不可用时：详情接口返回明确错误信息。
- SHOW COLUMNS 查询失败：返回空列表并携带提示信息。

## 测试
- 单元测试覆盖：
  - `mountPath` 为空时创建数据源
  - 详情接口：引擎列表、SHOW COLUMNS 裁剪逻辑

## 风险与对策
- **风险**：`mountPath` 为空时，现有导入/查询/维护接口仍会使用挂载路径解析，可能抛错。
- **对策**：本次仅变更新增与详情；若后续需要用系统导入/查询，请再单独调整路径解析策略。

## 关键决策
- 新增数据源不再强制要求挂载路径。
- 数据源详情展示 IGinX 层面的“全量引擎 + 全量路径”信息。
