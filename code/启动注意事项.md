# 项目启动注意事项

## 启动顺序
1. 先启动 IGinX。
2. 再启动后端（Spring Boot）。
3. 最后启动前端（Vite）。

## IGinX
- 启动脚本：`"E:/毕设/基于IGinX的数据与模型智能关联管理系统设计与实现/code/IGinX/core/target/iginx-core-0.9.0-SNAPSHOT/sbin/start_iginx.bat"`
- 配置文件：`"E:/毕设/基于IGinX的数据与模型智能关联管理系统设计与实现/code/IGinX/core/target/iginx-core-0.9.0-SNAPSHOT/conf/config.properties"`
- Java 要求：JDK 8 及以上，`JAVA_HOME` 必须已设置。
- 端口说明：IGinX 会监听多个端口（通常包含 6888），以配置文件和启动日志为准。
- 依赖服务：Zookeeper（默认 2181）与 IoTDB 实例需先启动。
- 构建提示：若 `mvn package` 报 `license-maven-plugin` 或 `spotless` 相关错误，使用 `-P !format -DskipTests` 重新构建。
- 冲突处理：若 `7888` 端口占用导致 REST 启动失败，需先停止旧的 IGinX 进程或修改 `restPort`。

启动命令（PowerShell）：
```powershell
Start-Process -FilePath "E:/毕设/基于IGinX的数据与模型智能关联管理系统设计与实现/code/IGinX/core/target/iginx-core-0.9.0-SNAPSHOT/sbin/start_iginx.bat" `
  -WorkingDirectory "E:/毕设/基于IGinX的数据与模型智能关联管理系统设计与实现/code/IGinX/core/target/iginx-core-0.9.0-SNAPSHOT/sbin" `
  -RedirectStandardOutput "E:/毕设/基于IGinX的数据与模型智能关联管理系统设计与实现/code/iginx-start.log" `
  -RedirectStandardError "E:/毕设/基于IGinX的数据与模型智能关联管理系统设计与实现/code/iginx-start.err.log"
```

## IoTDB
- 端口：常见为 `6667`/`6668`，确保与 IGinX 元数据一致。
- 账户：默认 `root/root`。
- 时间精度：需与 IGinX 的写入精度一致（当前写入为纳秒级）。

## 后端（Spring Boot）
- 启动命令：`mvn -f ".../iginx-assoc-backend/pom.xml" spring-boot:run`
- Java 要求：必须使用 JDK 17。
- 端口：默认 8080（如需更改请查看 `application.yml`）。
- 依赖 IGinX：后端会连接 IGinX，需确保 IGinX 已启动且端口配置一致。

启动命令（PowerShell）：
```powershell
$env:JAVA_HOME="C:/Program Files/Java/jdk17"
$env:PATH="$env:JAVA_HOME/bin;$env:PATH"
Start-Process -FilePath "mvn.cmd" -ArgumentList "-f","E:/毕设/基于IGinX的数据与模型智能关联管理系统设计与实现/code/iginx-assoc-backend/pom.xml","spring-boot:run" `
  -WorkingDirectory "E:/毕设/基于IGinX的数据与模型智能关联管理系统设计与实现/code" `
  -RedirectStandardOutput "E:/毕设/基于IGinX的数据与模型智能关联管理系统设计与实现/code/backend.log" `
  -RedirectStandardError "E:/毕设/基于IGinX的数据与模型智能关联管理系统设计与实现/code/backend.err.log"
```

## 前端（Vite）
- 依赖：已安装 Node.js 与 npm。
- 首次启动需先执行 `npm install`。
- 端口：默认 5173。

启动命令（PowerShell）：
```powershell
Start-Process -FilePath "npm.cmd" -ArgumentList "run","dev" `
  -WorkingDirectory "E:/毕设/基于IGinX的数据与模型智能关联管理系统设计与实现/code/iginx-assoc-ui" `
  -RedirectStandardOutput "E:/毕设/基于IGinX的数据与模型智能关联管理系统设计与实现/code/frontend.log" `
  -RedirectStandardError "E:/毕设/基于IGinX的数据与模型智能关联管理系统设计与实现/code/frontend.err.log"
```

## 日志与排查
- IGinX 日志：`iginx-start.log` / `iginx-start.err.log`
- 后端日志：`backend.log` / `backend.err.log`
- 前端日志：`frontend.log` / `frontend.err.log`
- Zookeeper 元数据：用于保存分片与存储单元信息，若数据分片范围异常需重点检查。

## 常见问题
- 后端编译报错 `无效的标记: --release`：说明使用了 JDK 17 以下版本，请切换到 JDK 17。
- 后端启动后提示无法连接 IGinX：确认 IGinX 已启动，且 `config.properties` 端口与后端配置一致。
- 端口被占用：检查 8080/5173/IGinX 端口占用情况，必要时停止冲突进程或改端口。
- 控制台出现 Spring Security 临时口令：这是开发环境的默认行为，生产环境需替换为正式安全配置。
- 时序数据缺段或仅显示部分：优先检查 IGinX Zookeeper 分片范围与 IoTDB 实例连通性。
- 如需直接用 IoTDB CLI 验证数据：IGinX 会在物理路径上追加 `iginx_tagkv` / `iginx_end`，IGinX 查询仍使用逻辑路径（如 `root.demo.temperature`）。
