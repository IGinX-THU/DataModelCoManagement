## 2. 项目背景与设计目标

### 2.1 业务背景与痛点

- 数据源类型多样（INFLUXDB/IOTDB/POSTGRESQL），接入和查询逻辑分散。
- 模型文件和模型元数据需要统一管理，并支持版本追踪。
- 规则驱动任务需要可追踪、可中断、可导出结果。
- 实验分析与报告生成需形成闭环能力。

### 2.2 设计目标

- 功能完整：覆盖“数据-模型-规则-任务-分析”闭环。
- 稳定可控：统一异常处理、任务状态可追踪、文件下载可校验。
- 可维护：模块职责清晰，Controller/Service/Repository 分层明确。
- 可扩展：预留数据源类型扩展与任务计算逻辑替换点。

### 2.3 设计约束

- 技术栈：Spring Boot 3.2 + JPA + PostgreSQL + IGinX Session SDK
- 运行环境：Java 17，默认端口 `8080`
- 文件上传限制：单文件/请求最大 `500MB`

### 2.4 非目标说明

- 当前版本安全策略为开发态放行（`permitAll`），不实现完整 RBAC。
- 不提供分布式任务编排，仅支持单实例线程池调度。

## 3. 总体架构设计

### 3.1 系统上下文与外部依赖

- 核心外部依赖：
- PostgreSQL：业务元数据持久化
- IGinX：时序数据与结构化访问入口
- IGinX 文件系统：模型大文件块存储
- 本地目录：导入错误文件、导出文件、报告文件

### 3.2 分层架构

- 接口层：`modules/*/controller`
- 业务层：`modules/*/service/impl`
- 持久层：`modules/*/repository`
- 领域对象：`entity/dto/vo`
- 框架层：`framework/iginx`、`framework/security`、`framework/storage`

### 3.3 模块划分

- 数据域：DataSource、DataImport、DataExport、DataQuery、DataMaintain、Structure
- 模型域：ModelAsset
- 规则域：AssociationRule
- 任务域：Task + TaskScheduler
- 分析域：Analysis（曲线、资源包、报告）
- 系统域：Dashboard、SystemSql、SystemLog

### 3.4 核心调用链

- 数据接入链：Controller -> DataSourceService -> 连接测试 -> 存储引擎注册 -> Repository
- 任务执行链：TaskController -> TaskService -> TaskScheduler -> IGinX -> TaskRepository
- 分析导出链：AnalysisController -> AnalysisService -> IGinX/文件服务 -> 下载链接返回

## 4. 核心业务流程设计

### 4.1 数据源接入流程

- 请求创建数据源。
- 校验类型、名称、挂载路径、连接配置。
- 执行连接测试。
- 时序数据源按需注册 IGinX StorageEngine。
- 连接配置加密后持久化。

- [图2：数据源接入流程图（draw.io）](./diagrams/html/latest/data-source-onboarding-flow.html)
- 源文件：`docs/design/diagrams/src/data-source-onboarding-flow.mmd`

### 4.2 模型上传与版本管理流程

- 校验文件与类型，解析 IO Schema。
- 新建或复用模型档案，设置版本号（支持自动递增）。
- 模型文件按分块写入 IGinX 文件系统。
- 历史版本 `is_latest=false`，新版本 `is_latest=true`。

- [图3：模型上传与版本管理流程图（draw.io）](./diagrams/html/latest/model-upload-version-flow.html)
- 源文件：`docs/design/diagrams/src/model-upload-version-flow.mmd`

### 4.3 规则编排流程

- 创建规则时校验模型输入/输出绑定完整性。
- 规则映射与输出目标序列化为 JSON 存储。
- 支持启停控制与运行中任务删除保护。

### 4.4 任务调度执行流程

- 提交任务后先落库 `PENDING`。
- 事务提交后进入线程池排队执行。
- 执行期更新 `RUNNING`，计算后写回输出测点。
- 成功/失败/中止收敛到终态，并写入执行日志。

- [图4：规则驱动任务执行时序图（draw.io）](./diagrams/html/latest/rule-task-sequence-seq.html)
- [图6：任务状态流转与调度流程图（draw.io）](./diagrams/html/latest/task-state-flow-flow.html)
- 源文件：`docs/design/diagrams/src/rule-task-sequence-seq.mmd`、`docs/design/diagrams/src/task-state-flow-flow.mmd`

### 4.5 分析导出与报告流程

- 查询任务曲线、任务对比曲线。
- 资源包导出（模型、输入、输出、元数据、README）并打包 ZIP。
- 报告生成（统计 + 图表数据）并输出 PDF。

- [图5：分析导出与报告生成时序图（draw.io）](./diagrams/html/latest/analysis-export-report-sequence-seq.html)
- 源文件：`docs/design/diagrams/src/analysis-export-report-sequence-seq.mmd`

### 4.6 异常与回滚策略

- 统一异常由 `GlobalExceptionHandler` 转换为 `Result.error`。
- 业务异常统一使用 `BizException(code, message)`。
- 任务异步提交失败场景补写 `FAILED` 状态，避免悬空任务。

## 5. 模块详细设计

### 5.1 系统管理模块

- `SystemController`：健康检查、日志查询、SQL 控制台。
- `DashboardController`：统计汇总、趋势、最近任务。
- `SystemSqlServiceImpl`：多类型 SQL 结果规整输出（包含时间格式化）。

### 5.2 数据源管理模块

- `DataSourceServiceImpl` 负责：
- 创建/更新/删除数据源
- 挂载路径规范化（IOTDB/INFLUXDB 差异处理）
- 存储引擎注册/卸载与残留冲突检查
- 数据结构预览（时序树 + 结构化 schema/table）

### 5.3 数据导入导出模块

- 导入：
- 时序导入：CSV/Excel 读取 + 批量写入 + 错误行回写文件
- 结构化导入：CSV/Excel/SQL 三通道，支持冲突策略与自动建表
- 导出：
- 同步或异步导出（结构化数据量阈值估算触发异步）
- 支持 CSV/JSON/EXCEL
- 导出任务持久化并可查询状态

### 5.4 数据查询与维护模块

- 时序查询：支持下采样与聚合类型映射。
- 结构化查询：动态构建 where/order，过滤软删除行，内存分页。
- 结构化维护：统一以 `KEY` 或 `_iginx_key` 定位行，insert 覆盖更新。

### 5.5 模型资产模块

- 上传、解析、下载、删除版本与档案。
- 文件存储采用分块写入 IGinX（`DataType.BINARY`）。
- 版本删除后自动回补 `latest` 标记。

### 5.6 关联规则模块

- 规则绑定校验直接依赖模型 IO Schema。
- 规则删除受运行中任务保护。
- 映射 JSON 结构化存储，便于任务执行时反序列化。

### 5.7 任务模块

- `TaskScheduler`：固定核心线程池 + 有界队列（100）。
- `TaskServiceImpl`：任务全生命周期状态管理。
- 任务计算策略：按输入路径读取数据，计算输出并写回输出路径。

### 5.8 分析报告模块

- 曲线查询、任务对比、资源包导出、PDF 报告生成。
- 报告图表默认下采样，控制 PDF 体积和渲染性能。

## 7. 数据库详细设计

### 7.1 核心实体

- `sys_data_resource`：数据源定义与连接配置
- `meta_model_profile`：模型档案
- `model_asset`：模型版本资产
- `association_rule`：规则定义
- `task`：任务执行实例
- `data_export_task`：导出任务状态

### 7.2 主关系约束

- `model_asset.profile_id -> meta_model_profile.id`
- `association_rule.data_id -> sys_data_resource.id`
- `association_rule.model_id -> model_asset.id`
- `task.rule_id -> association_rule.id`

### 7.3 ER 图

- [图7：核心数据模型 ER 图（draw.io）](./diagrams/html/latest/core-er-model-er.html)
- 源文件：`docs/design/diagrams/src/core-er-model-er.mmd`

### 7.4 索引与查询建议

- 高频查询字段：`task.create_time`、`task.rule_id`、`association_rule.enabled`
- 建议补充组合索引：`task(rule_id, create_time)`、`association_rule(model_id, enabled)`

### 7.5 一致性策略

- 同步业务写使用事务（`@Transactional`）。
- 异步任务提交采用“事务后调度”确保任务记录先落库。

## 8. 存储与文件设计

### 8.1 模型文件存储

- 存储服务：`ModelFileStorageService`
- 存储介质：IGinX 文件系统（按 chunk 写入）
- 存储路径：`iginx://{model-root}/{framework}/{profileId}/{version}/{filename}`

### 8.2 数据导出与错误文件存储

- 存储服务：`DataFileStorageService`
- 默认目录：`assoc.storage.data-root`（默认 `storage/data`）
- 文件类型：`zip/pdf/csv/json/xlsx`

### 8.3 下载安全

- 下载接口禁止 `..` 路径穿越。
- 校验目标路径必须在根目录下。
- 不存在文件直接返回业务错误。

## 9. 安全设计

### 9.1 认证授权

- 当前配置为开发态全放行（`permitAll`）。
- 生产建议引入 JWT 鉴权与接口分级权限。

### 9.2 输入校验

- DTO 使用 `jakarta.validation` 注解校验必填与范围。
- 控制层使用 `@Validated` 与 `@Valid`。

### 9.3 敏感信息保护

- 数据源连接配置入库前通过 `ConnectionConfigCipher` 加密。
- 返回前密码字段只暴露掩码值。

### 9.4 典型风险点

- SQL 控制台存在高权限操作风险，应加白名单或角色限制。
- 文件下载需要持续保持路径白名单校验。

## 10. 异常处理与可观测性

### 10.1 异常处理

- `BizException`：业务异常（可控错误）
- `MethodArgumentNotValidException`：参数校验失败
- `Exception`：兜底为 500

### 10.2 日志策略

- 使用 `slf4j` 分类记录 warn/error。
- 关键失败链路包含 requestId 便于追踪。

### 10.3 可观测建议

- 建议增加指标：
- 任务提交成功率
- 导入导出耗时
- 任务队列长度
- IGinX 连接重试次数

## 11. 性能与容量设计

### 11.1 任务并发能力

- 调度器线程数：`max(1, CPU-1)`
- 队列容量：100
- 队列满时返回 503（系统繁忙）

### 11.2 导入导出批次策略

- 时序导入批次：10000
- 结构化导入批次：2000
- 文件查询分块：1024

### 11.3 报告生成控制

- 报告图表最大点位：600（下采样控制）

### 11.4 容量建议

- 大文件场景优先异步导出。
- 生产建议将本地导出目录迁移至持久化挂载盘。

## 14. 风险评估与应对

### 14.1 技术风险

- IGinX 连接不稳定导致查询/写入失败。
- 应对：封装层重连一次并提供统一错误返回。

### 14.2 数据风险

- 错误导入导致脏数据。
- 应对：导入错误明细文件输出 + 关键字段校验。

### 14.3 性能风险

- 大量导出阻塞请求线程。
- 应对：异步导出 + 任务状态查询。

### 14.4 安全风险

- SQL 控制台误操作高危语句。
- 应对：生产环境关闭或加权限白名单。
