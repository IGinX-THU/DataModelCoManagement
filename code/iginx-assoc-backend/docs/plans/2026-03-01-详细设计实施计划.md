# IGinX 关联管理后端详细设计实施计划

## 1. 计划目标

- 基于现有后端源码，完成一份可交付的详细设计文档。
- 文档必须覆盖既定大纲的全部章节，且内容与当前实现一致。
- 对关键章节补充可视化图示（draw.io）：架构图、流程图、时序图、ER 图、部署图。
- 输出可追溯的设计资产：正文文档、图源文件、draw.io 打开入口、清单文件。

## 2. 输入与约束

- 输入资料：
- `docs/API文档.md`
- `docs/openapi.yaml`
- `src/main/resources/sql/schema.sql`
- `src/main/java/com/xmu/iginx/assoc/modules/**`
- 约束：
- 仅基于当前代码事实编写，不虚构未实现能力。
- 统一使用中文描述，关键术语可保留英文。
- 图示使用 draw.io 兼容产物，保留 Mermaid 源内容用于可维护性。

## 4. 工作分解（WBS）

### 阶段 A：基线梳理（已完成）

- 任务 A1：接口清单梳理（52 个业务接口 + 别名路由）
- 任务 A2：数据库结构与实体映射梳理
- 任务 A3：核心服务流程梳理（数据源、模型、规则、任务、分析）
- 产出：设计输入清单
- 验收标准：关键模块职责和调用链路可追溯到代码文件

### 阶段 B：详细设计规划

- 任务 B1：按大纲拆解章节目标与写作粒度
- 任务 B2：定义每章所需图示类型与插入位置
- 任务 B3：确定文档内统一格式（术语、编号、图号、引用规范）
- 产出：章节级编写方案 + 图示规划表
- 验收标准：每章有明确“输入、输出、完成定义”

### 阶段 C：正文编写

- 任务 C1：完成第 1~3 章（背景、目标、总体架构）
- 任务 C2：完成第 4~8 章（流程、模块、接口、数据库、存储）
- 任务 C3：完成第 9~13 章（安全、可观测、性能、测试、部署）
- 任务 C4：完成第 14~15 章（风险、附录）
- 产出：完整正文初稿
- 验收标准：大纲章节覆盖率 100%，无空节

### 阶段 D：图示资产生成（draw.io）

- 任务 D1：编写 Mermaid 源图（流程/时序/ER/架构/部署）
- 任务 D2：通过 Python 生成 draw.io 压缩 URL HTML
- 任务 D3：生成稳定链接和清单（manifest + README）
- 产出：图源 + draw.io 入口文件
- 验收标准：每张图均可通过对应 HTML 打开 draw.io

### 阶段 E：联调与校验

- 任务 E1：将图链接嵌入正文对应章节
- 任务 E2：校验图号、章节号、路径引用一致性
- 任务 E3：校验文档术语和字段命名一致性
- 产出：可交付终稿
- 验收标准：
- 章节覆盖率 100%
- 图文引用无断链
- 核心流程与代码实现一致

## 6. 风险与应对

- 风险 R1：源码注释/异常信息存在历史编码污染，影响文档语义。
- 应对：以方法行为和字段语义为主，不直接照搬乱码文本。
- 风险 R2：draw.io URL 长度较大且易损坏。
- 应对：仅通过脚本生成，不在文档正文手输 URL。
- 风险 R3：接口文档与实现漂移。
- 应对：以 Controller + Service 实现为准并做逐项核对。
