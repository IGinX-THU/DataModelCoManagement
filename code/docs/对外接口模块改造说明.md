# 对外接口模块改造说明（RESTful + Java + Python）

## 🎯 一、改造目标与交付范围

本次改造围绕“对外接口模块”完成了以下目标：

- 提供统一的 RESTful 对外接口，覆盖：
  - 模型调用
  - 算法调用
  - 数据导入
  - 数据导出
- 对四类能力统一成“异步作业”模型：
  - 提交作业
  - 查询状态
  - 查询结果
- 补齐 Java / Python SDK（薄封装）
- 提供 cURL / Java / Python 示例
- 补齐 OpenAPI 契约与专项文档

---

## 🧩 二、核心设计（你现在系统里是什么样）

### 1) 统一异步作业模型

新增了一个统一作业域 `ExternalJob`，对外所有能力都走同一套生命周期：

- `PENDING`（已提交）
- `RUNNING`（执行中）
- `SUCCEEDED`（成功）
- `FAILED`（失败）
- `CANCELED`（取消）

这样做的作用：

- 外部系统接入方式统一，不需要关心内部任务执行细节
- 长耗时任务不会阻塞 HTTP 请求
- 状态、结果、错误模型标准化，便于 SDK 封装

### 2) 外部门面层复用内部能力

本次没有推翻原有业务逻辑，而是通过“门面编排”复用已有模块：

- 模型调用 → 复用 `TaskService`
- 算法调用 → 复用 `AnalysisService`
- 数据导入 → 复用 `DataImportService`
- 数据导出 → 复用 `DataExportService`

这样做的作用：

- 改动小、风险低
- 与现有系统能力一致，不引入双轨逻辑
- 后续扩展能力时只需在门面层扩展

## 🚀 三、对外 REST 接口（新增）

接口统一前缀：`/api/v1/external`

- `POST /api/v1/external/model-jobs`
  - 提交模型调用作业
- `POST /api/v1/external/algorithm-jobs`
  - 提交算法调用作业
- `POST /api/v1/external/data-import-jobs`
  - 提交数据导入作业（`multipart/form-data`，包含 `request + file`）
- `POST /api/v1/external/data-export-jobs`
  - 提交数据导出作业
- `GET /api/v1/external/jobs/{jobId}`
  - 查询作业状态
- `GET /api/v1/external/jobs/{jobId}/result`
  - 查询作业结果

## ⚙️ 五、后端执行逻辑改造（关键行为）

服务实现文件：

- `E:/毕设/基于IGinX的数据与模型智能关联管理系统设计与实现/code/iginx-assoc-backend/src/main/java/com/xmu/iginx/assoc/modules/external/service/impl/ExternalJobServiceImpl.java`

### 1) 模型调用作业

- 入参：`ruleId + timeRange (+ pollIntervalSeconds + timeoutSeconds)`
- 内部行为：
  - 提交内部任务（`TaskService.submitTask`）
  - 轮询内部任务状态直到结束
  - 将内部结果封装到 External 结果中

作用：

- 对外只需关心一个 `jobId`
- 内部任务细节被屏蔽

### 2) 算法调用作业

通过 `action` 区分算法动作，当前支持：

- `TASK_SERIES`
- `TASK_COMPARE`
- `TASK_EXPORT`
- `TASK_REPORT`

内部复用 `AnalysisService`，返回标准化结果对象。

### 3) 数据导入作业

- 先把上传文件落到临时文件
- 作业线程中再交给 `DataImportService`
- 结束后清理临时文件

作用：

- 提交请求更快返回
- 上传大文件时不阻塞请求线程

### 4) 数据导出作业

- External 层统一异步，但内部调用 `DataExportService` 时强制 `async=false`
- 由 External 作业线程承接异步行为并收敛结果

作用：

- 外部契约统一为“External 作业异步”
- 避免内部导出异步再套一层异步导致双层状态管理复杂

### 5) 错误码映射

增加统一错误对象 `ExternalErrorResponse`，典型错误码：

- `INVALID_ARGUMENT`
- `RESOURCE_NOT_FOUND`
- `EXECUTION_FAILED`
- `TIMEOUT`
- `PERMISSION_DENIED`
- `CANCELED`
- `INTERNAL_ERROR`

## 💡 九、这次改造对系统的价值

### 对接入方

- 接口语义统一：全部通过 `jobId` 追踪
- 调用方式简单：REST + Java/Python SDK + 示例齐全
- 失败定位更直接：统一错误码 + traceId

### 对系统演进

- 外部门面层与内部业务层解耦
- 后续新增能力可按“新增作业类型/动作”扩展
- 文档、契约、SDK 三者对齐，降低维护成本

---

## ⚠️ 十、当前注意事项

- Maven/测试需使用 JDK17（JDK8 会因 `--release` 和 target 版本报错）。
- `docs/API文档.md` 原文件存在历史编码问题，本次新增了独立文档 `External接口文档.md` 保证可读性与可维护性。
- External 模块复用了现有 `TaskScheduler` 线程池；后续如果外部并发很高，建议评估独立线程池与队列容量。
